SPIDEY-DECOMP — GODOT TRACK
============================
Fan learning remake of a Spider-Man-style action game in Godot 4.
PC-only (Windows x64 primary). Non-commercial. Quality bar: ~2010-era.
Built level by level; this file tracks Godot-side progress.

GOTCHAS
-------
- One edit_file per FILE per batch (same-file parallel edits race).
- LevelBase._connect_actors counts only Thug: bosses wire downed manually
  (level sets enemies_total = 1, thugs auto-added after).
- Area3D triggers must not overlap walkable decks (docks water y[-4,-1]).
- CharacterBody3D has no auto-step: ramps for height, coplanar ground
  (streets sidewalks flush, theater stage coplanar), never stair boxes.
- Test walk phase moves ~9 m: keep boss triggers 4+ m past walk end
  (theater trigger z<6 from spawn 18.5: walk ends ~z10, margin 4 m).
- ExitGate/thug scenes drive level flow; LevelBase.debug_defeat explodes
  barrels via has_method("detonate") and hits bosses via take_hit.
- gdparse/gdlint catch syntax+style, NOT undeclared vars: hud.gd once
  shipped without _player/_msg_tween/_dmg_tween/_result_shown (fixed L4).
- Shaders/particles are NOT validated here (no engine): keep to minimal
  standard features (web shader avoids fwidth; FX avoids curves/damping).
- Never put backslash escapes (\\t, \\n) inside shader-code strings: a
  stray backslash fails shader compile at runtime (hero went pink-risk);
  use literal tabs/newlines in the """ block. True-web math (atan +
  fract spokes/rings) is the approved suit pattern, shared red + blue.
- edit_file fuzzy-matches whitespace: after single-line-anchor edits,
  verify indentation with sed (docks splash needed a fix once).
- Levels add_child() actors BEFORE setting positions: _ready cannot use
  global_position (hostage variants use instance-id hash instead;
  civilian captures home on first physics frame).
- find_children on code-built nodes needs owned=false (owner is null);
  `as` casts only objects - never `as Vector3` (use typed locals).
- Mysterio APPEAR spins rig.rotation.y freely; TAUNT re-faces absolutely
  after, so no drift. Same pattern is safe for any looping rig spin.
- Engine.time_scale tricks need a generation guard + restore points:
  _hitstop restores only for the latest gen; _on_died and
  Game._do_change_level force 1.0 (slow-mo never leaks across death
  or scene changes).
- Player reads Thug.State.STAGGER/STUNNED for finishers (global-class
  enum access). Bosses use different State enums - never compare them.
- collision_layer = 0 is a valid ghost (detected by nothing); the mask
  still drives move_and_slide (civilian: layer 0 / mask 1).
- Annex/side areas must hold ZERO enemies unless gating counts are
  updated too (all 6 annexes/piers/plazas are enemy-free by design).
- Thug rig variant reads scale.x in _ready: set scale BEFORE add_child
  (docks bruiser was post-add and silently missed bruiser styling).
- Rotated-box ramps: bury the low edge in the floor, land the top edge
  coplanar-or-buried in the platform (bugle landings, theater balcony).
- 6m roof gaps need full sprint jumps (7.5 v0 + 9.5 run ~ 6.5m range);
  never widen jump gaps past 6m without a swing anchor nearby.
- ProcTex dress runs post-_build on scriptless StaticBody3D boxes only
  (rotation/size/color guards); actors, water, ramps and emissive or
  transparent boxes are skipped, so new deco boxes are textured only
  if they look like ground (flat + 8 m + neutral/green/brown) or
  towers (6 m tall + neutral). Keep gameplay paint saturated.
- "enemies" group doubles as the hittable set: Barrel + Breakable join
  it so punches/slams/webs/tracers hit them free (layer 5). Anything
  that must tell actors from props filters by `is` (test_runner does;
  civilian cower skips non-CharacterBody3D). New breakables: HP via
  take_hit only, never join "cars"/boss groups.
- Face decals: ProcTex.face_quad() paints unshaded transparent quads;
  parent to the head pivot (follows look-around), offset just outside
  the skin surface (sphere r + 0.005). Faces stay readable at night
  because they are unshaded; never shade them.
- Never describe code from memory: read first, then claim. (Twice
  burned: hero eyes/emblem/pattern + rhino eyes were claimed missing
  from memory and all existed. The user's trust is worth the re-read.)
